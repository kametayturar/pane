Cause: `selected` is never set when the page loads, so the Book button's handler throws before it does anything. In book(), the 10:30 slot looks selected only because the template adds the CSS class `sel` when `i === 1`. The variable `selected` (declared with `let selected`, so undefined) is assigned only inside the slot's click handler. The Book handler starts with `await fetch("/api/book", { body: JSON.stringify({ slot: selected.id }) })`, and `selected.id` throws "TypeError: Cannot read properties of undefined (reading 'id')" while building the request. Because the handler is async, the error becomes an unhandled promise rejection: no UI change, no request, nothing for the user to see, which is exactly "does nothing". Evidence (puppeteer + Chrome, page http://localhost:7003/#book): - On load the DOM shows slot s2 highlighted (class sel) while `selected` is undefined. - Click "Book appointment" without touching a slot: result div stays empty, the request log shows no POST /api/book at all, and the page reports pageerror "Cannot read properties of undefined (reading 'id')". - Click the 14:00 slot first (selected becomes {id:"s3",time:"14:00"}), then Book: the POST /api/book is sent and the page shows "Booked 14:00". So the button works, the highlighted default is the problem. Second bug hiding behind it: once the click works, the app shows "Booked 14:00" even though POST /api/book returned 404 here (the handler never reads `res`). Failures are reported to the user as success. Suggested fix (not applied, the task was to diagnose): initialise the selection from the same source as the highlight (`let selected = SLOTS[1]`, or render `sel` from `selected`), disable the button until a slot is chosen, and check `res.ok` before showing the success message.
