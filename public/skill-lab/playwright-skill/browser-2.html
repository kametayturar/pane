Result

Cause: in the Book page, the click handler does `fetch("/api/book", { body: JSON.stringify({ slot: selected.id }) })`, but the module-level `selected` is only assigned inside the slot click listener. The 10:30 slot is rendered with the "sel" class (i === 1) so it LOOKS selected, yet `selected` is still undefined. Clicking "Book appointment" without first clicking a slot throws TypeError: Cannot read properties of undefined (reading 'id') inside the async handler, before any request is made. The rejection is swallowed by the event handler, so the UI does nothing. Evidence: Playwright captured pageerror "Cannot read properties of undefined (reading 'id')", no /api request, and an empty #result div on the first click. After clicking the 10:30 slot explicitly, the same button sends POST /api/book {"slot":"s2"} and the page shows "Booked 10:30" – which proves the cause. Fix: initialise `selected = SLOTS[1]` when rendering (match the visual default) or render no default highlight. Second defect seen on the working path: the code never checks res.ok. My static server has no API, so POST /api/book returned 501 and the page still said "Booked 10:30"; the success message should depend on res.ok.
